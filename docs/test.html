Tóm Tắt Tổng Quan (Executive Summary)

Đánh giá hiện trạng kiến trúc, mức độ ổn định và các rủi ro vận hành quan trọng nhất

Hệ thống SMASH-VN được thiết kế theo mô hình phân tầng Spring Boot tiêu chuẩn kết hợp JPA/Hibernate, Spring Security và cơ sở dữ liệu SQL Server. Hệ thống vận hành đồng thời 2 kênh: Bán hàng trực tuyến (Online Cart/Checkout, thanh toán SePay QR, tính cước GHN) và Bán hàng tại quầy (Admin POS, Quản lý tồn kho FIFO theo lô nhập PhieuNhapChiTiet, Quy trình đổi trả hoàn tiền).

Kiến trúc cốt lõi ổn định: Cơ chế quản lý tồn kho FIFO (InventoryLotService) kết hợp khóa bi quan (PESSIMISTIC_WRITE) và quy trình xử lý thanh toán tự động SePay IPN Webhook có tính Idempotency cao, chống race condition và trừ tồn kho chính xác.
Hạng mục ưu tiên tối ưu:
  • Trang Admin Quản trị đơn hàng (/admin/don-hang): Cần chuyển từ findAll() sang Server-side Pagination với JPQL Constructor DTO để triệt tiêu N+1 Query.
  • Luồng Guest Checkout: Cần cho phép khách vãng lai đặt hàng bình thường ngay cả khi SĐT đã tồn tại trong database (không chặn đơn).
  • Test Fixtures: Cập nhật test fixtures trong InventoryFlowFullVerificationTest (gán nhanVien NOT NULL) để đạt 100% Passed.

AUDIT-001

N+1 Query & Thiếu Phân Trang Database Tại Danh Sách Đơn Hàng Admin

HIGH CONFIRMED
File: AdminController.java (66-158), HoaDon.java
Tác động: Tải toàn bộ bảng HoaDon vào RAM; sinh ra hàng trăm query phụ mỗi lượt load.
Trong AdminController.hienThiDanhSachDonHang(), phương thức gọi trực tiếp hoaDonRepository.findAll(...). Entity HoaDon chứa 5 quan hệ @ManyToOne không khai báo LAZY (mặc định EAGER trong JPA). Đồng thời, các trường @Formula cho GHN tracking và Refund Status chạy subquery trên từng dòng.
GET /admin/don-hang -> AdminController.hienThiDanhSachDonHang() -> hoaDonRepository.findAll(Sort.by(Direction.DESC, "ngayTao")) // Load ALL rows from DB -> Thymeleaf render donhang-list.html -> Hibernate executes N subqueries for each related entity & @Formula
Khuyến nghị khắc phục: Chuyển sang sử dụng JPQL Constructor Projection với DTO chuyên biệt (AdminHoaDonDTO) kết hợp Pageable ở mức Database (server-side pagination 10/20/50 rows) và lọc trực tiếp qua SQL WHERE cho 3 tab: Đơn Online, Đơn POS, Đơn Đổi Trả.

AUDIT-003

Khách Vãng Lai Bị Chặn Đặt Hàng Nếu SĐT Trùng Với Tài Khoản Đã Đăng Ký

MEDIUM CONFIRMED

AUDIT-004

Cấu Hình Open-Session-In-View (OSIV) Mặc Định Chưa Tắt

MEDIUM POTENTIAL RISK
File: application.properties
Tác động: Giữ kết nối Database Connection Pool (HikariCP) suốt toàn bộ vòng đời render HTML Thymeleaf.
Trong application.properties, thuộc tính spring.jpa.open-in-view chưa được set thành false. Spring Boot mặc định bật OSIV, cho phép lazy-loading tại tầng Controller/View nhưng tiềm ẩn nguy cơ cạn kiệt connection pool khi traffic tăng cao.
Khuyến nghị khắc phục: Thêm cấu hình spring.jpa.open-in-view=false và chủ động fetch dữ liệu cần thiết tại Service layer thông qua DTO hoặc JPQL JOIN FETCH.

Kiểm Toán Chuyên Sâu (Security, Concurrency & Performance)

Phân tích an ninh bảo mật, kiểm soát đua lệnh và hiệu năng mở rộng production

1. Bảo Mật & Chống Tấn Công

  • IDOR Tra cứu đơn hàng: Endpoint /tra-cuu-don-hang yêu cầu cặp xác thực maHoaDon + soDienThoai, ngăn chặn kẻ tấn công dò mã đơn tuần tự.
  • Bình luận độc hại (XSS): Bình luận sản phẩm và bài viết được lọc qua ProfanityFilter kết hợp CommentModerationScheduler quét định kỳ tự động gắn cờ vi phạm.
  • Upload Ảnh An Toàn: Phương thức upload đổi tên file sang định dạng UUID.randomUUID() + extension, vô hiệu hóa hoàn toàn nguy cơ Path Traversal hoặc ghi đè file hệ điều hành.

2. Kiểm Soát Đua Lệnh (Concurrency)

  • Khóa Tồn Kho Sản Phẩm: Sử dụng LockModeType.PESSIMISTIC_WRITE với hint updlock,holdlock,rowlock trên bảng SanPhamChiTiet trong lúc thanh toán.
  • Khóa Phiếu Giảm Giá: Áp dụng findByMaPhieuWithLock đảm bảo voucher giới hạn lượt dùng không bị trừ âm khi nhiều khách bấm thanh toán cùng thời điểm.
  • Xác Nhận SePay Idempotent: Kiểm tra trạng thái đơn CHO_THANH_TOAN trước khi xử lý, nếu SePay gửi nhiều webhook trùng lặp thì các lần sau bị bỏ qua an toàn.

Kết Luận Cuối Cùng & Lộ Trình Triển Khai (Final Verdict)

Kế hoạch hành động chi tiết từng bước cho đội ngũ phát triển

ĐÁNH GIÁ CHUNG: Dự án SMASH-VN có nền tảng kiến trúc nghiệp vụ rất vững chắc. Hệ thống giao dịch (Thanh toán SePay, Tồn kho FIFO, Đổi trả GHN) đã được trang bị khóa đồng thời và tính toàn vẹn dữ liệu tốt. Sau khi hoàn thành việc tối ưu hóa trang Admin Đơn Hàng và chuẩn hóa Guest Checkout, hệ thống hoàn toàn đủ điều kiện vận hành Production quy mô lớn.

Lộ Trình Ưu Tiên Xử Lý:

  1. Bước 1 (Ưu tiên số 1): Nâng cấp trang /admin/don-hang sang Server-side Pagination với JPQL Projection AdminHoaDonDTO để triệt tiêu hoàn toàn vấn đề N+1 Query.
  2. Bước 2 (Ưu tiên số 2): Nới lỏng kiểm tra SĐT trong Guest Checkout (GioHangService) để không chặn khách vãng lai khi SĐT đã tồn tại trong database.
  3. Bước 3 (Ưu tiên số 3): Cập nhật test fixtures trong InventoryFlowFullVerificationTest (gán nhanVien mặc định khi tạo SanPham) để toàn bộ 518 test cases đều đạt 100% Passed.
  4. Bước 4 (Ưu tiên số 4): Bổ sung cấu hình spring.jpa.open-in-view=false trong application.properties để tối ưu hóa việc giải phóng Connection Pool.
